# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Try the demo" button on the sign-in page gives a stranger a private, pre-filled landlord workspace that can't send email and is deleted after 24 h.

**Architecture:**
- A new `DemoModule` (`apps/api/src/demo/`) creates a demo organization and owner, seeds it through the real services, and starts a session.
- `Organization.demoExpiresAt` marks demos. `SessionContext.demo` carries the flag, so `SessionGuard` can refuse `@DemoRestricted()` routes.
- `MailerService` drops mail for demos.
- `JobsService.runAll` deletes expired demos.
- In the web app, the auth page gets the button, and the app shell gets a banner.

**Tech Stack:** NestJS 12 / Fastify, Prisma 6 / PostgreSQL 17, Angular 22 (signals), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-20-demo-mode-design.md`

## Global Constraints

- `DEMO_ENABLED` defaults to `false`. `DEMO_MAX_ACTIVE` defaults to 25 (range 1–200). The lifetime is 24 h.
- `POST /demo`: `@Public()`, `@RateLimit(3, '1 hour')`.
- Error codes:
  - `DEMO_UNAVAILABLE` (503): "The demo is busy right now. Try again in a little while, or create your own workspace."
  - `DEMO_RESTRICTED` (403): "Not available in the demo. Create your own workspace to use this."
- Demo user email: `demo-<uuid>@demo.rentflow.invalid`. Workspace name: "Demo Rentals". `requireOwnerMfa = false`.
- Mail log event: `MAIL_SUPPRESSED_DEMO`.
- Sample data is created through `RentalSetupService`, `BillingService.runBilling` and `PaymentsService.create`, never raw ledger inserts. Peso rents are ₱6,500–₱18,000; tenant emails use `@example.com`; phones `0917 000 xxxx`.
- Web: no `styles:` in components, no static `style=""`. Page styles go in `src/styles/_pages.scss` under the host tag; shell styles in `_shell.scss`. Use tokens; motion only behind `prefers-reduced-motion: no-preference`.
- Commits are small and per layer (API, then web, then docs). Messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Don't push without asking.

## Review Focus

1. **Two clicks at once, or a double-click:** each click creates its own demo. That's fine, but the cap check and the insert must not let the count go over `DEMO_MAX_ACTIVE` by more than the in-flight requests. Task 2 tests that 3 parallel creates at cap−1 leave at most cap−1+3 live demos, and that every response is 201 or 503.
2. **A demo session used after its workspace has been cleaned up:** the next request must get a 401 (session gone), never a 500. Tested in Task 4.
3. **A real workspace with `demoExpiresAt` null must never be deleted,** even when the clean-up is called directly with its id. Tested in Task 4.
4. **A visitor types a real email into a tenant record, then tries portal invite, staff invite, or mail retry:** no mail is enqueued. Tested in Task 3 (count of `MailOutbox` rows for the org stays 0).
5. **Seeding fails partway** (a DB error mid-seed): no half-built demo left behind that counts toward the cap without being usable. Task 2: on seed failure, the demo org is deleted with the Task 4 delete function (built as part of Task 2) before rethrowing. Test it by making `runBilling` throw once.
